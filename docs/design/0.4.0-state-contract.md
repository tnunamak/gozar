# 0.4.0 embedding state contract

Queries retain schemaVersion 1. Catalog and RouteView responses use schemaVersion 2.
This separates operational support, local setup observations, and route proof: a
detected installation is not a verified route. No new provider calls are required.

## Field inventory

`Fact<T> = { known: true; value: T } | { known: false; reason: string }`.
Provider-service facts that have not been queried use reason `needs-provider-call`.
Local unavailable evidence uses `not-observed`; absent evidence is never false.

Configuration actions remain available when setup is ready. Apps submit edited
values through runSetupAction and replace secrets through storeSecret plus the
same approved action. Neither path opens a route. Changed values invalidate
subsequent catalog grants through existing plan/consent validation.

## Adapter data and observation boundary

Definitions declare operational availability and static decision facts. The
runtime keeps definition metadata separate from dynamic properties. Detect-only
kinds remain visible with reasons but never receive a candidate token. Missing
local prerequisites can be fixed through setup actions; account entitlement,
remote quotas and dashboard mappings stay unknown with needs-provider-call.

Host password, app restart, and chosen app port are host inputs. Gozar reports a
target only where its own route record contains one. TCP confidentiality remains
unknown. LAN means local network, not membership in the owner's devices.

## CLI and example

The CLI keeps its existing text. Structured projections own cleanup and proof
classification; rendering consumes the classification. Existing copy tables
remain presentation data. The shipped example accepts exactly --fakes or
--detect, uses only public exports, removes its private home under ~/.tmp, and
never creates a real route. Fake scenarios cover every admitted usage kind and
detected, verified, expired and cleanup-unconfirmed projections.

## Verification argument

Expect it to work because detection, setup descriptors and lifecycle records
already supply these independent observations. Fake journeys and schema
conformance check the contract; unchanged expose UX tests pin human output.
The uncertain premise is remote account knowledge: explicit unknown facts keep
that uncertainty visible until a separately authorized provider call exists.
