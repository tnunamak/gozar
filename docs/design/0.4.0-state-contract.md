# 0.4.0 embedding state contract

Queries retain schemaVersion 1; Catalog and RouteView responses use 2. Detection,
operational availability, prerequisites and proof are independent. A detected
installation does not establish that Gozar can create a route.

## Small core and promotion rule

Promote a fact into the typed core only when an app must compute with it: branch,
compare, sort or gate. Display alone is insufficient. A core change is a semver
event. New facts are data rows and require no schema, type or app changes.

The existing computation core remains: reach/audience, payload readers and TLS
termination, address/stability, cost kind, lifetime, stop, prerequisites and route
proof. Existing descriptive Properties members remain for 0.3 compatibility;
new display details belong in facts rather than expanding Properties.

`Observation<T> = {known:true,value:T} | {known:false,reason:string}`.
The provider-call unknown reason is `needs-provider-call`. A local fact that was
not observed uses `not-observed`. Unknown never means false. Legacy nullable
Properties members remain, but new state fields use explicit observations.

## Open facts

`Fact = {id:string,label:string,value:string|number|boolean|null,known:boolean,
reason?:string,group:string,affectsConsent:boolean,source:string,asOf:string|null}`.
Unknown facts require a nonempty reason; their null value is a placeholder, never
an assertion of absence. Known false is `known:true,value:false`. Adapters declare
rows in definition.json; runtime observations may supply additional rows without
changing the shape. Groups are open strings. Initial groups: privacy, account,
limits, cost, address, configuration, setup, terms, access and details.

Source is the shipped evidence reference; asOf is the evidence accessed date or
null when unrecorded. Current account entitlement, remaining quota and effective
remote mapping are unknown with needs-provider-call. Static terms links, cost
summaries, address conditions and evidenced public-name/certificate behavior are
rows. TCP payload confidentiality remains unknown; LAN means Local network.

Consent rule: apps must show every affectsConsent row before approval. Existing
CLI payload-reader sentences are rows with affectsConsent true and occupy their
existing slots. Additional consent rows render generically. Non-consent rows are
CLI verbose details. This preserves the 0.3.4 default text. Apps must not parse
message, display or disclosure.text to compute decisions.

## Setup boundary and host ownership

Input requirements are descriptor driven. storeSecret never returns a secret.
runSetupAction validates syntax and approval, persists plain values or secret
bindings, and supports editing and rotation even while setup is ready. Public
read-back never returns credential bytes or secret handles. Credential presence
does not establish account entitlement. Existing route edits do not silently
reconfigure a running route: stop and obtain fresh catalog consent to replace it.

Host password, restart policy and app port pin remain host inputs. Gozar exposes
only recorded route targets; bindTarget stays unknown unless observed. No real
provider mutation is part of these changes.

## Verification

Expect it to work because adapter data, local setup storage and route lifecycle
records already contain these separate facts. Deterministic tests cover every
adapter, typed secret setup/edit/rotation, all usage kinds and lifecycle states,
and add a new fact row through the testing API with no example change. Existing
expose UX tests pin human text. The --detect example is read-only and exits 0
when providers are missing; --fakes uses only Gozar testing exports. Both remove
their private home under ~/.tmp.

## Execution and extension seam (Lead ruling, supersedes execution exclusion)

Named tunnels and SDK listeners execute through attached usage. Adapters own
provider setup, start, observation, verification and stop; the common attached
controller owns the lease, gate, proof-before-publication and cleanup retry state.
A provider is one module plus definition data registered in a manifest. Public
`createGozar({manifest,root})` loads that registry with the existing loader's path
and schema checks. The controller persists the registry reference in its private
bootstrap, so a new provider survives the process boundary without core edits.
A module is trusted executable code; this seam does not load untrusted uploads.

The lifecycle remains setup -> plan/consent -> create -> verify -> observe ->
remove. No origin is published before proof. A failed create must clean up its
partial runtime before rejecting. A failed proof invokes removal. Removal that
cannot establish absence returns debt, which the public view reports as cleanup
unconfirmed; closing again retries. An attached runtime must not outlive its
controller: SDK handles close at process exit; child processes receive parent
stdin EOF and terminate. Removal acts on the runtime handle created by that
adapter, never on a provider-wide name. Provider status details are open facts.

Cloudflare's adapter takes a private tunnel token and a configured HTTPS origin.
Its process receives the token through its environment, never command arguments
or return values. The remote dashboard must already map that origin to the
configured local target; that remote fact stays needs-provider-call until proof
establishes the effective route. Gozar starts the connector, not a DNS rule or
remote tunnel registration. ngrok adapters use the optional SDK and accept
credential and address input requirements. TLS/TCP claims remain distinct:
opaque TCP does not establish confidentiality, and an origin that cannot pass
Gozar's HTTP(S) proof must remain unverified rather than being advertised.

The public configuration vocabulary is input requirements, for generic data collection.
`Configuration.inputRequirements: InputRequirement[]` replaces `fields` in this
unreleased contract. Each descriptor is `{id,label,kind,secret,required,help,
obtainUrl,validation}`: kind is text/domain/https-origin; secret is boolean;
help is adapter-authored text; obtainUrl is string or null; validation remains
syntax-only. Embedders own their UI. CLI setup can prompt from these descriptors
without provider branches. Both this descriptor change and createGozar are
recorded in the public types, schema and migration guide.

The installed-tarball test adds a provider only in its fixture registry and walks
setup, start, proof, stop and cleanup through the public factory. No shipped core
file changes to admit it. Existing new-fact rendering remains a separate test.
Real-account tests are opt-in scripts with environment credentials. They are
not run here and are not a release gate; no user token or live exposure is used.


### Protocol-independent proof seam

`Adapter.prepareProof?(ctx:ReadContext, request:AdapterRequest)` returns an
`AdapterProofSession` with target, verify({origin,receipt}) and close(). It creates
a fresh attempt-bound challenge before provider create. Its target replaces the
original target in plan effects. verify returns status, checkedAt, optional
validUntil, vantage, checks and optional open facts. The controller publishes only
on verified status, withdraws on later failure, and closes the proof session with
the provider lifecycle. Existing adapters without this hook retain their HTTP
gate. `AdapterDefinition.originSchemes?:string[]` permits protocol URL schemes
from data (including colon); the generic validator forbids credentials, path,
query and fragment. TLS/TCP implementations are assigned to the parallel lane.
The extension fixture will use non-HTTP proof to test the seam independently.


### Final protocol and refresh semantics

ProofAttempt carries id, fresh nonce, deadlineMs and cancellation signal. verify
receives the attempt and returns attemptId plus endpoint; core rejects mismatches,
late results and cancellation. Properties.transport and Requirements.transport
include tcp/tls as a 0.4 semver change. AdapterProofSession.refresh is optional;
without it, status retains the original checkedAt/validUntil and never repeats
initial verification. Expiry withdraws published state. No published stream gate
switches ordinary new application connections into proof mode.

Consent-relevant facts participate in the approved disclosure revision. Static
and runtime facts remain open rows. Classification rows 25–48 supply explicit
needs-provider-call rows for remote clocks, refusal, entitlement, credential
validity, traffic policy, DNS authority, renewal, authorization and residue.
Observed route/proof facts are network observations, not inferred local truth.
The separate host application journey remains host-owned.

A named HTTPS connector uses a configured stable local gate port; its dashboard
service mapping must point there. The proof gate then forwards to the consented
app target. Proof failure leaves the origin unpublished. Stopping closes only
the owned connector and gate. Tunnel registration, DNS and token revocation are
external owner operations and remain explicit facts. Real-account walks use CLI
descriptor prompts and Gozar-stored credentials, never env-token scripts.

### Review closure: API boundaries and cleanup debt

0.4 public CLI/session starts use admitted operational plans, not the minimal
legacy Rust recipe proof. The daemon rejects a non-operational selected bootstrap
for publication. Old journals remain eligible only for identity-scoped local
cleanup through recoverStop. Internal Rust legacy unit fixtures are not a public
0.4 creation API. Operational proof keeps its richer receipts; attached adapters
use HTTP gate proof or the declared bound protocol hook; durable/external service
verification uses the service challenge. These paths have different ownership
and cleanup responsibilities and are not one universal verifier.

`GozarThrownError.route?: RouteView` (also optional in the CLI error envelope)
returns a partial attached route when startup failed with unresolved cleanup.
This is typed because the app must compute the exact closeRoute handle. The
controller remains available for exact-handle retry while cleanup is unconfirmed;
unknown startup outcomes do not imply no allocation. Once cleanup is confirmed,
the controller exits. SDK close acknowledgement alone is insufficient when a
runtime/SDK read-back says the exact listener is still active; absent ownership
records alone never confirm remote absence. Owner domains, addresses, credentials
and remote registration remain separately retained resources.

### Host embedding, consent-v1 and controller identity

The frozen embedding contract uses distinct setup and route consent scopes.
`Action.consent: {scope: SetupConsentScope; consentFactsDigest: string}` comes
from the offered action, current configuration revision, registry identity and
consent facts. Setup approval carries `kind: 'setup'`; route approval carries
`kind: 'route'`. Unknown expected route origin is null. Setup has no route fields.
`Candidate.consentFactsDigest: string` and `review.canonicalInput` expose the
exact review snapshot. Unknown digests are not approved. This breaks 0.3 approvals.

`consent-v1` recursively sorts JSON object keys in code-unit order and sorts facts
by id. It preserves ordered arrays, rejects duplicate fact IDs and ambiguous
JSON, normalizes unknown values to null with a reason, and distinguishes known
false, zero, empty string and null. Observation timestamps and display-only facts
are excluded. UTF-8 JSON is SHA-256 hashed with prefix `consent-v1:`. Negative
zero encodes as zero. Golden input and digest live in consent-facts.test.mjs.

`registryId: string` is `registry-v1:` plus a content hash of manifest, provider
modules/data and wrapped recipe bytes. Installation paths are excluded. The
controller checks the expected hash before adapter effects; unknown identity
refuses execution. Custom host callbacks remain in the parent. An authenticated
private broker carries configuration lookups; only its socket/token/instance/boot
descriptor crosses bootstrap. No host credential bytes enter Gozar files or env.

`verification.subject: {origin,target,instanceId,handleGeneration,bootId}|null`
comes from the current proof-producing controller incarnation and bound receipt.
Unknown subject is null, never invented from an origin alone.
`verification.observedAt: string|null` is the actual proof observation time,
never a status-render time. A fresh controller has a fresh boot even when the
embedding factory survives. These fields are additive; requiring subject-bound
proof and revision-bound setup is a deliberate 0.4 authorization change.

`Query.operationId?: string` is a host-journaled idempotency key, scoped to home
and owner. Its durable reservation contains canonical registry/provider/config,
usage/target/origin/requirements/consent intent and a stable handle before effects.
Token bytes and observation times are excluded. Same key and intent returns the
original current handle, including starting or uncertain recovery; a conflicting
intent raises `operation_conflict`. A crash never makes the reservation a command
to allocate again. `RouteView.operationId: string|null` is null for legacy records.
`listRoutes({home,owner?}): Promise<{routes:RouteView[]}>` reads persisted owned
route/recovery snapshots without renewing proof or minting authority. Unreadable
state rejects. Confirmed stop is retained for terminal replay. These are additive
fields; the host must record its key before calling to obtain crash recovery.
