# Operational plan wire delta (gozar-plan/1)

Full definitions opt in with `planVersion:1` and `admission:{state:"admitted",requiredFeatures:[...]}`. Features must be supported by BOTH core and `host.features`. Missing/unknown features block the whole plan. Existing definitions stay gated until normalized; opaque adapter IDs have no meaning in Rust.

Top-level input adds trusted private `host:{nowMs,features,bindings,facts,probe}`. This is host-driver authority, never renderer/user answer data. `nowMs` is supplied, monotonic, and never read from a clock. Bound host facts carry `{value,authorityRef,sessionId,observedAtMs,expiresAtMs}`. Typed host bindings carry `{type,value?,handleRef?,authorityRef,sessionId,observedAtMs,expiresAtMs,mode?,parentMode?}`; private values are opaque handles, never paths or bytes.

A create/remove recipe has bounded `before:[{id,recipe,captures?,assert?}]`, `requires:[assertion,...]`, executable fields, `after:[{id,recipe,captures?,assert?}]`, and optional `ledger:{...expected exact nonsecret record...}`. Maximum 16 steps on each side; nested sequences are rejected. Preflight recipes are observations only. Mutation intent is emitted only after all fresh before steps, bindings and requires pass. All after readbacks must pass before probe/publication or cleanup success. Failure after dispatch retains resource/uncertainty debt.

Every operational effect adds `recipeRef` (`<operation>/before/<id>`, `<operation>/execute`, `<operation>/after/<id>`), `stepId`, `stage` (`before|persist|execute|after|probe`), `bindings` (validated typed records), and `bindingRefs` (name→authorityRef). Driver must resolve THIS exact adapter recipe path and compare THIS effect's executable fields, not recursively search commands. Persistence record includes exact execute payload, bindings, baseline facts and ledger. Private handle placeholders remain in argv for driver resolution under the typed authority.

`captures` is a name→spec map. Specs: `{type:"bool|port|dns-name|opaque-ref|origin|mount",pointer:"/raw/path"}`, `{type:"record",fields:{name:spec,...}}`, and `{type:"port-set",paths:["/map","/nested/*/map",...]}`. Only explicitly captured typed nonsecret facts survive; raw provider documents/output never do. Port sets collect every numeric/host:port map key across supplied paths; unknown key syntax fails closed. Capture output lives at `facts[stepId]`; requires `source:<stepId>` reads that captured object (not the raw document). Step `assert` reads the transient document directly. JSON predicates all/items or rules, not/predicate or rule, equals, exists remain supported.

Bindings: root binding specs use `type` plus literal `value`, trusted host binding of same name, or `{source:"stepId",pointer:"/captured/path"}`. Types include `literal`, `loopback-port`, `port`, `mount`, `dns-name`, `loopback-http-origin`, `credential-free-https-origin`, `selected-interface-address`, `opaque-private-reference`, `session-private-path`, `reserved-unused-port`. Generic port choice is `{type:"unused-port",source:"config",pointer:"/occupiedPorts",candidates:[9443,9444,9445],protectedPorts:[443,10000]}`. Selection only considers explicit candidates, checks all captured occupied ports, and never invents fallback. Public plans list only 8443. Literal private 9443 plans remain blocked when occupied. `"{name}"` as entire JSON value retains its type; interpolation into strings is literal text. No shell/eval.

Assertions: JSON predicates; `{op:"verified",fact:"id"}` requires scoped unexpired host receipt; `{op:"private-file",binding:"id",mode:"0600",parentMode:"0700"}` requires session-owned private handle receipt; `{op:"port-unoccupied",source:"config",pointer:"/occupiedPorts",port:"{port}"}`; `{op:"exact-route",source:"readback",pointer:"/route",expected:{...}}`; `{op:"owned-ledger-match",source:"live",pointer:"/route"}` compares the whole exact record with resource ledger AND requires fresh host ownership continuity receipt; `{op:"owned-route-absent",source:"readback",pointer:"/route"}` requires explicit null/missing capture. All parameters are explicit; old schema-shaped assertions without source/pointer/expected must be normalized, never guessed.

Process `process:{mode:"owned-long-running",stdin:"closed",lifetimeMs:900000}` becomes typed owned-process start policy on spawn. `owned-process` remove uses immutable `resourceId` plus exact `ownership` receipt; PID alone is never authority. `local-forwarder` uses the same immutable ownership receipt. Other process metadata is rejected unless supported explicitly. Create completion must return `ownership:{handleRef,continuityRef,kind:"process|forwarder|route",sessionId,generation,details:{...exact ledger fields...}}`. Before cleanup, return `ownershipReceipt:{handleRef,continuityRef,sessionId,observedAtMs,expiresAtMs,continuous:true}` alongside current readback. Unknown continuity blocks deletion. Late allocations remain cleanup debt.

Operational probes require trusted `host.probe:{nonceRef,verifierRef,expiresAtMs}` and completion `probeReceipt:{nonceRef,verifierRef,origin,vantage,observedAtMs,expiresAtMs,tls,instanceMatched,sse,streamableHttp,oauthDcr}`. Identity, nonce, origin, vantage, expiry and requested protocols must match. Nonlocal vantage requires `remote:true`, except public vantage may use an original trusted `host.probe.allowPublicRelay:true` challenge with receipt `remote:false,networkPath:"public-relay",publicDns:true,resolvedIp:<public-unicast IP>`. LAN/tailnet are unchanged. Local execution is never relabeled remote. No external probe service is implemented in core.

Initial feature names: `recipe-sequence`, `typed-bindings`, `predicate-parser`, `owned-resource-ledger`, `owned-process`, `interface-forwarder`, `private-file-reference`, `probe-assertions`, `client-vantage-probe`, `unused-port-selection`. Private config materialization remains unsupported and blocks affected complete plans.


A `session-private-path` binding may declare `provision:"install-ed25519"` with the `install-ed25519` feature. After consent the host creates or reuses an installation identity, then copies it to an owned session-private handle; neither private bytes nor paths enter core state.

A URL parser may declare `jsonEvent:{eventPointer,eventValue,originPointer}` with the `json-event-origin` feature. It considers only matching JSON objects and subjects the selected value to the same exact-origin and anchored hostname constraints. `originPolicy:"immutable"` with `immutable-origin` withdraws a process route on a valid different announcement and requires a new session; health checks cannot publish the replacement.
